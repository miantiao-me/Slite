# 数据备份与恢复

## 链接备份

保存在 `/data/backups` 目录下的应用备份属于**链接 JSON 导出，而非完整数据库快照**。它们不包含进程内基于 unstorage memory 驱动的内存短链接缓存、DuckDB 访问分析、上传的图片文件，也不包含全部应用状态。内存缓存会自动重建，无需恢复。请将备份文件另存到宿主机外部：保存在同一块硬盘上的备份无法抵御磁盘损坏风险。

自动链接备份默认每天执行一次，保留最近 30 份自动备份。手动触发的备份不会被自动清理。在运行环境设置 `NUXT_DISABLE_AUTO_BACKUP=true` 可停用自动备份；手动备份功能仍可正常使用。

恢复兼容的导出链接时，使用常规的[导入 API](/zh-CN/features/import-export) 即可。导入并非全实例恢复，且不会覆盖已存在的活跃短链码。

## 完整备份

获取一致性的全量备份步骤如下：

1. 使用 `docker compose stop` 停止容器，确认没有其他进程仍在使用该数据目录。
2. 将宿主机或数据卷中**挂载的整个 `/data` 目录**完整复制或打包，包括 `slite.sqlite` 及其附属文件（若存在）、`analytics.duckdb`、`files/images` 和 `backups`。
3. 将部署配置、密钥与当前应用版本号一同妥善保存在安全位置。
4. 使用 `docker compose start` 启动容器。

切勿在 Slite 运行时仅复制主数据库文件。运行中的文件系统直接拷贝无法保证数据一致性。

## 完整恢复

停止 Slite，将之前备份的完整目录还原至本地数据卷，确保容器运行用户具有读写权限，然后启动对应版本的应用镜像。切勿将快照直接合并进运行中的实例。在重新引入业务流量前，请验证登录、重定向、图片显示与访问分析功能。

短链接缓存使用 unstorage memory 驱动且仅存在于运行进程中，启动后会按需从 SQLite 回填，因此无需恢复缓存数据。
